# 界面语言（中文 / English）

> 设置 → 常规 → 「语言 / Language」在中文和 English 之间切换。灵动岛、设置窗口、右键菜单、托盘、会话小鱼、聊天窗、
> 各种气泡与错误提示都跟着换；给模型的提示词和内容性的文字不换。

## 模块

| 文件 | 职责 |
|---|---|
| `pet/i18n.py` | 查表层：`t(key, **values)`、`maybe_t`、`set_language` / `current_language`、键名校验 |
| `pet/locale/zh.json`、`pet/locale/en.json` | 两张扁平的「键 → 文字」表；中文表的值就是原来写在代码里的字 |
| `pet/config.py` | 配置键 `ui_language`（`zh` / `en`，默认 `zh`）；当前语言的**唯一写入者** |
| `pet/settings_language.py` | 设置页那一行（下拉显示语言自称：「中文 / English」） |
| `pet/settings_dialogue_text.py` | 事件名表、模板参数表（中文是内部标识）和它们的显示函数 |

## 机制与不变量

### 查表

- `t("island.card.chat")`：当前语言查表 → 缺了退回中文 → 再缺退回键名。**用户看到的最坏情况是中文，不是键名。**
- 占位符用命名的 `{名字}`，多给的值不碍事，格式化失败返回未填的原文。
- 英文单复数：英文表里写成 `<键>.one` / `<键>.other` 一对（中文表只有 `<键>`），`t(key, n=…)` 按 `n == 1` 自己挑。
- 键名：小写英文、点分命名空间、下划线连词，至少两段（`settings.ai.show_key`、`menu.action.<id>`、`chat.window.…`）。
  前缀按界面分：`settings.*`、`menu.*`、`chat.*`、`island.*` …；批量生成的键是「前缀 + 英文前几个实词」。
- 当前语言是 `i18n` 里的一个模块级变量，所以纯函数（算「3 分钟前」、汇总会话数）不用拿到 `Config` 也能 `t()`。
  代价：测试里每新建一个 `Config` 都会把语言设回它的配置值——英文用例要先把 `ui_language` 写进那份配置。
- `maybe_t(value)`：是表里的键就翻译，否则原样返回。给「默认值是键、调用方也可以传现成文字」的参数用（文件对话框过滤器、置灰原因）。

### 不变量

- **中文界面逐字不变**：中文表的值 = 改造前的字面量，既有按中文断言的测试不用改。
- 两张表键集合一致（英文允许用 `.one` / `.other` 对代替一个键）、没有空文案、键名合规；代码里 `t("…")` 用到的键都在中文表里。
- 两边的 `{占位符}` 和 `%` 说明符一致。
- 配置里存的值不翻：下拉的取值、编排里的子菜单名、快捷启动项名字、彩蛋标题都按原样存。

### 新增文案的步骤

1. 代码里直接写 `t("<前缀>.<名字>")`，不要先写中文字面量再回头改。
2. `zh.json`、`en.json` 各加一条（逐行插入，不要重新序列化整份文件）；带数量的英文句子加 `.one` / `.other`。
3. 新菜单动作：`ACTION_LABELS` 加中文名的同时，两张表加 `menu.action.<id>`。
4. 跑守卫：`tests/test_i18n.py`（两表一致、代码里的键都在）、`tests/test_settings_english.py`（英文设置窗里没有中文、
   没有按钮被定宽截断）、`tests/test_menu_english.py`、`tests/test_rest_english.py`、`tests/test_island_english.py`。
   `test_i18n` 只认字面量形式的 `t("…")`；拼出来的键（`f"menu.action.{id}"`）要自己有用例守着。
5. 英文比中文长：按钮用最小宽度而不是定宽，看一眼真实字体下有没有被截断。

### 导入时求值的表：存键，用时翻译

模块级常量、默认参数、导入时就实例化的对象里**不能调 `t()`**——那一刻语言还没定（设置进程碰巧是先建 `Config` 再导入设置模块，
测试和其他进程不保证）。做法是常量里存文案键，显示的那一刻再 `t()` / `maybe_t()`。
例：`MenuActionRegistry()` 在导入时实例化，它的置灰原因存的是键名字符串，由 `disabled_reason()` 翻译。

### 内部标识保持中文，显示时翻译

这些表里的中文被测试、深链、配置或别的模块当标识用，不动数据，只在显示时按 id 取文案：

| 表 | 显示函数 |
|---|---|
| `SETTINGS_DOMAIN_NAV`（侧栏域名；`select_page` 中英文域名都认） | `domain_label` |
| `DIALOGUE_LABELS` / `DIALOGUE_PARAMS`（事件名、模板参数） | `dialogue_label` / `dialogue_param` |
| `ACTION_LABELS`、`CUSTOM_ICON_CHOICES`（菜单动作名、图标选项） | `MENU_ACTIONS.label()`、`icon_choice_label()` |
| 模板自带的子菜单名（`SUBMENU_LABEL_KEYS`） | `MENU_ACTIONS.default_label(node)` |
| `CHAT_UI_STYLE_LABELS`（对话窗口风格名） | `chat_style_label` |
| `claude_hooks.PHASE_TEXT`（会话状态词） | 本身是按当前语言取值的 `Mapping`，仍可当字典用 |
| `claude_session_info.ENTRY_TEXT`（会话来源） | `entry_text` |

会被存进配置的名字（编排里的子菜单名）用「还是内置原文吗」判断：是就按语言显示，用户改过就原样。
模板原名改过的话，旧名也要留在 `SUBMENU_LABEL_KEYS` 的原名元组里，否则旧编排里那一项永远显示中文。

### 「按文字找某一项」要钉到键上

代码里有按 `action.text()` 找锚点的地方（把新项插到「退出」前、「隐藏肥鱼」接在「退出子肥鱼」后）。
比较的一侧必须用建菜单时的**同一个键**（`t("menu.shared.quit")`），不能写中文字面量，也不能赌两边英文碰巧相同。
以后再要「按文字找某一项」，用同一个键，或者改用 `objectName` / property 做身份。

### 运行中切语言

- 设置窗口是另一个进程，主进程靠 `Config.reload()` 得知语言变了。`reload()` 里 `set_language` 必须取**磁盘上的新值**（`raw`）：
  那一行在白名单合并之前执行，取 `self.data` 的话会把旧语言又设一遍——配置里是新语言，`t()` 和提示词却按旧语言走到重启。
- `Config` 的加载、`set`、保存也都会同步一次语言。
- 灵动岛有两条链，都挂在既有的配置重载上：岛自己写的字（按钮、占位、表头、菜单）在 `refresh_from_config` 里重写、面板 `retranslate()`；
  主进程算好塞给岛的字（会话计数、最近对话、卡片标题）由 `AppShell._repush_island_texts` 重推。
  占位文案（「余额 --」）只在显示的仍是任一语言下的占位值时才重写，有真实数据的不动。
- 右键菜单、托盘菜单每次弹出都重建，下次打开即是新语言。
- 已经开着的设置窗口、简报窗口不会就地刷新，重开生效。已生成的简报 / 笔记不重译。
- 简报、工作笔记给模型的提示词有中英两套，按 `current_language()` 选，见 [工作助理](work-assistant.md)。

## 设计取舍

- **键用英文标识符，不用中文原文做键**：改中文措辞不会悄悄弄丢英文，同词异译天然分开。代价是所有文字都要进表。
- **不用 Qt 的 `tr()` / `.ts`**：要上 `lupdate` / `lrelease` 工具链，表也不是人能直接改的 JSON。
- **切语言不要求重启**：现有的配置重载链路够用。
- **只有中文 / English 两项**，没做「跟随系统」；要加是 `normalize_language` 里多一个值。
- **英文要拟人一点**：休息中 → *Napping*，等你批准 → *Needs your OK*，工作简报 → *Daily Briefing*；时间用 *11 min ago*（胶囊放不下 *minutes*）。
  措辞要换直接改 `en.json`，不动代码。
- **有意不翻的**：
  - 给模型的提示词（识屏、拖文件解读、知识库工具说明、主动识屏的活动分类）：模型按用户语言回复，提示词语言不影响界面。
  - **被当判断依据的字符串**：聊天窗靠在错误文案里找「认证失败 / 未授权 / 授权」判断是不是认证问题，这几个词必须是字面量——
    换成 `t()` 后英文界面会去找英文词，漏掉中文错误。批量改写后要专门查这一类。
  - 会存进配置的内容默认值：彩蛋标题「厉害了我的鲸 / 请点击」。
  - 内容名：角色名、动画名、对话背景主题名、节日语录、报时语录。内置台词不走查表，而是另有英文数据文件，见 [台词与语音](persona-and-voice.md)。
  - 旧拓扑：`PetWindow`、`app.py` 的兜底托盘菜单（只修崩溃）。日志、注释、文档。
- **主体叫「肥鱼」，不叫「桌宠」**：项目就叫 BigFatFish，菜单里早有「生小肥鱼」「主肥鱼」，两个字也比「桌面助手」省地方；英文是 *the fish*。
  没有抽「名字常量」（一百多处界面字符串分散在几十个模块，再改名就再跑一次整词替换）。配置键和标识符是 ASCII，不受影响。
  新文案别再写「桌宠」；目前中文表里只剩旧版聊天窗的三条（`chat.classic.*` 的「跟随桌宠」）没改。

## 排障

| 症状 | 原因 / 先查什么 |
|---|---|
| 设置里换了语言，运行中的肥鱼没换（或只换了一半） | `Config.reload()` 里语言取值的顺序；`tests/test_language_reload.py` |
| 界面上直接显示 `some.key.name` | 键在两张表里都没有：多半是拼出来的键漏加了 |
| 英文界面里零星的中文 | 走查表但英文表缺那条（退回中文），或那处还是字面量；模块级常量最容易漏 |
| 新设置行让 `test_settings_english` 红了 | 「英文窗里没有中文」拦住了漏网的字面量；确实有意保留的（语言自称、内容名、中文示例）在那个用例里登记 |
| `t()` 报「不可调用」或 ruff F402 / F823 | 局部变量或循环变量叫 `t`，遮住了翻译函数，改名 |
| 英文按钮被截成「hoose」「Previe」 | 定宽按钮：改成最小宽度 |
| 英文菜单里某一项位置不对（没插到「Quit」前） | 按文字找锚点的地方没用同一个键 |
| 测试里表头断言少了最后一个字母 | 测试环境的回退字体更宽，显示被省略：断言未省略的全文 `header_text` |
