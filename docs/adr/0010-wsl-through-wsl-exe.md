# 0010：WSL 里的东西经 `wsl.exe` 探测和写，不吵醒没在运行的发行版

日期：2026-11-02、2026-11-10

## 背景

用量、会话小鱼、记忆蒸馏、配置全景都要读 WSL 里的文件，有的还要写。最直接的办法是把 `\\wsl.localhost\<发行版>`
当成普通目录用，实测有三个问题：

- 访问共享会把发行版拉起来。每分钟读一次，发行版就永远关不掉。
- 发行版没起来时，对共享路径做 `stat` / `exists()` 会卡几秒甚至报错。把共享目录当根逐个 `stat` 扫一遍要 2.6 秒。
- 经共享做原子替换，会把文件权限从 600 重置成 644。

## 决定

- **先问再读**：用 `wsl.exe --list --running` 确认发行版在运行，只读在运行的。定时任务不叫醒没在运行的发行版。
- **探测走 `wsl.exe`**：在发行版里用 `find` 列出文件和大小（0.13 秒），共享只用来读确实变长了的文件。
- **写走 `wsl.exe`**：内容经标准输入送进去，在发行版里写临时文件再 `mv`，路径有白名单，保留原权限。
- 这些调用都在后台线程里，不在 GUI 线程起 `wsl.exe`。

## 后果

- 发行版没开着时，相关内容显示为「读不到」（例如用量显示 `WSL --`），不是 0，也不会去拉起它。
- 每次探测要起一个 `wsl.exe` 进程，所以不能做成高频轮询。
- 只支持默认发行版的场景较多；被重写成同样大小的文件认不出变化。
- 测试里不能起真的 `wsl.exe`：`tests/conftest.py` 已经拒绝，新增的调用点照此打桩。
