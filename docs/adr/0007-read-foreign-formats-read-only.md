# 0007：读别家程序的内部格式时只读，读不到就少一条线索

日期：2026-10-12

## 背景

会话小鱼、跳到对话、用量、通知跳转、记忆蒸馏都需要别的程序没有公开的信息：Claude Code 的会话记录和运行清单、
VS Code 的窗口清单和状态库、Windows 的通知库、Claude 桌面版的深链。这些都没有文档，升级就可能变。

## 决定

可以依赖这些内部格式，但守四条：

- **只读**。sqlite 以只读方式打开；通知库先复制成副本再查，从不碰活文件。
- **读不到不报错**。每一处读取失败都退回「不知道」或老路：少一条线索，功能变钝，而不是坏掉。
  新线索只能让结果更准，不能让原来能用的变成不能用。
- **不缓存、不自己另记一份**。每次现读（都是毫秒级），省掉失效问题；例外是对方进程退出后就拿不到的信息
  （工作区、桌面版会话 id），趁活着记进肥鱼自己的历史。
- **依赖写进文档**。每份主题文档有「外部格式依赖」一节，列出路径、键名、字段，升级后先核对那里。

不读的东西：Claude 桌面版的私有会话库（单文件几百 KB、形状随时会变），宁可功能少一点。

## 后果

- Claude Code、VS Code、Windows 升级后，这些功能可能悄悄变差而不报错；排查时先看对应文档的「外部格式依赖」。
- 新增一处对内部格式的依赖，要同时写降级路径和文档条目。
- 用户看到的是「内容留空」而不是错误提示，问题不容易被注意到。
