# 0003：两个账号各走各的通道，内容不互通

日期：2026-10-12（2026-11-10 扩展到记忆蒸馏）

## 背景

这台机器上有两个 Claude 账号：肥鱼聊天用的个人 API key，和 WSL 里 Claude Code 登录着的公司账号。
后者挂着 Slack、工单、日历等连接器，前者没有。工作简报、Slack 关注、工作笔记、公司侧的记忆蒸馏都需要读公司的内容。

## 决定

公司的内容只由公司账号处理：肥鱼在 WSL 里无界面运行 `claude -p`，由那个账号自己读、自己总结，肥鱼只拿结果来显示和存档。

- 那条命令只放行读取类工具，内置工具整个关掉，写入类工具点名拒绝。
- 公司侧的文字不进个人 key 的提示词。记忆蒸馏里有逐字断言的测试守着这条。
- 一段会话记录算哪一侧，只看它的工作目录：Linux 路径和配置里划出的公司目录算公司侧，其余算个人侧。
  不看是从哪个程序打开的，也不看聊了什么。
- 肥鱼起的每一次无界面运行都带 `BIG_FAT_FISH_HEADLESS=1`，它不冒会话小鱼，也不被认领。

没有选「把公司内容交给个人 key 来总结」：那等于把公司数据发给另一个账号。
也没有选「让肥鱼追问简报」：追问要把简报内容带进个人 key 的对话。

## 后果

- 公司侧功能都依赖 WSL 里登录着的 Claude Code 和对应的连接器；它们不可用时这些功能整体不可用。
- 肥鱼的聊天看不到简报、笔记的内容，不能就它们接着问。
- 在 Windows 路径下聊公司的事会被归到个人侧，只能靠把那个目录划进公司目录来纠正。
- 新增任何「让那个账号看一眼」的功能，照这条通道做，并带上无界面标记。
