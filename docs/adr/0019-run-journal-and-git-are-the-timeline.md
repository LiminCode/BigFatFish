# 0019：时间轴有两本账——肥鱼做的事记运行记录，仓库里的事问 git，靠提交号对上

日期：2026-11-22

## 背景

配置全景是某一刻的截面：谁连着谁、此刻差多少。它答不了「昨晚九点半发生了什么」。2026-11-22 查出个人知识库的克隆
落后远端 46 个提交、9 天没人拉取，而这期间云端的 Claude 会话一直在往远端写——肥鱼这边没有任何地方看得到这件事。
接下来要给知识库加定时同步（每小时、停笔后、启动和唤醒时），定时的东西一多，更需要一条时间轴：什么时候触发了什么、
对仓库做了什么。现有各个定时功能（简报、Slack 关注、蒸馏）的状态文件都只留最后一次，没有历史。

## 决定

- **两本账，不合成一本。** 仓库里发生了什么，git 自己就是账本（提交、作者、时间），不另存一份。肥鱼做了什么
  （哪个任务、被什么触发、每步多久、成没成）只有肥鱼知道，记在**运行记录**里（`pet/run_journal.py`）。
- **靠提交号对上。** 一次运行在「效果」里写下同步前后远端分支的提交号、它推上去的提交号。能对上某次运行的提交是肥鱼
  做的；对不上的就是外部写入（云端会话、别的机器），在时间轴上单独成行。
- **运行记录只记元数据**：没有正文、没有提交说明、没有文件名。要看这些，页面展开时现从 git 读。
- **只留本机，按月分文件，留 90 天。** 存储表里登记为日志、丢了不要紧。不进任何仓库。
- **一个进程一本、追加写。** 一次运行一行 JSON；「效果」是通用的列表（现在只有 `git` 一类），加一类不改格式。
- **磁贴上的历史条、每个任务此刻的状态、瀑布流页，都从这一本算出来**，不各存各的。
- 没事可做的运行（`noop`）照样落盘，页面上折叠显示。

考虑过又没选的：

- **把远端的提交也抄进运行记录**：两处会不一致，而且把提交说明（知识库的内容）带出了仓库。
- **运行记录也进私有仓库**：它的价值是诊断；每次运行一个提交会淹没知识库自己的历史。
- **只存每个任务的最后一次**（现有各功能的做法）：答不了「该跑没跑」「上周哪天开始失败」。
- **`noop` 不落盘、只累加计数**：省空间，但丢了「它确实每小时都在跑」的证据，而「迟了」正是要靠这个判断。

## 后果

- 时间轴上关于仓库的那一半永远和 git 一致，因为它就是 git；代价是画时间轴要 fetch 过才看得到别人的提交。
- 丢了运行记录，仓库的历史一条不少，只是不再知道某个提交是哪次运行、为什么触发的。
- 新增一个定时任务或同步器时，必须经 `Journal.start(...).finish(...)` 记一行；触发原因和结果只能取登记过的值
  （`TRIGGERS` / `RESULTS`），否则当场抛。自己另存一份「上次运行」是违反这条决定的。
- 往运行记录里写正文、提交说明或文件名，是把内容带出仓库：不许。`error` 只留报错的末 200 个字符。
- 90 天是按「一天约 150 次运行、三个月约 2.4 MB」定的；任务多了先调保留期，不改成数据库。
