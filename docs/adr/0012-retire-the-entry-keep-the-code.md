# 0012：下线一个功能时只摘入口，能力代码和配置键留着

日期：2026-10-14

## 背景

本项目围绕 Claude Code，从上游带来的一些功能不再需要入口：DeepSeek 余额与 Harness、DSH 开关、本地音乐播放器的启动、
右键菜单里的「音乐」和「显示本轮消费」。这些功能的代码和别的模块交织在一起，用户保存过的菜单编排和配置里也还有它们。

## 决定

下线只做三件事：从菜单模板和设置页摘掉入口；把被删的菜单动作和子菜单的 id 登记进配置里的丢弃清单，
用户的旧编排加载时自动清掉；被删的配置键在加载时丢弃。

能力代码和仍在用的配置键保留：余额查询、Harness 启动器、DSH 监视器、歌词与唱歌联动、消费结算。
老配置里开着的照旧生效。

例外是有明确成本的代码直接删掉，例如每次启动为了找本地播放器扫几个盘符（3～5 秒）。

没有选「连能力代码一起删」：它们被别处引用，逐处拆掉的风险和工作量大于留着的阅读成本。

## 后果

- 仓库里有一批没有入口的代码（`pet/balance.py`、`pet/harness_launcher.py`、`DshMonitor` 等）。它们是有意留下的，
  要整个删掉时先查各主题文档里记的「谁还在用」。
- 菜单编排里只有隐藏，没有删除：真正删掉的 id 必须进丢弃清单，漏登记的会在菜单编辑器里显示成「此平台不可用」。
  子菜单的 id 和动作的 id 是两张清单。
- 丢弃是不可逆的：回滚代码后，被清掉的条目不会回到用户的编排里。
