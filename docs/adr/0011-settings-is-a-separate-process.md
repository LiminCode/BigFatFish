# 0011：设置窗口是独立的单实例进程

日期：沿用上游的设计（2026-09），2026-10-21 补充前台规则

## 背景

设置页第一次打开时加载的字体、样式和模块，在进程里没法卸载。肥鱼是常驻程序，为一个偶尔打开的窗口长期背这份内存不值。

## 决定

设置窗口是另起的进程（`python -m pet --settings`），用锁文件保证只有一个。

- 设置进程不导入主进程的应用模块；两边只通过配置文件通信：设置进程写盘，主进程监视文件变化后 `Config.reload()`。
- 设置已经开着时再点「肥鱼设置」，按锁文件里的进程号找到那扇窗并调到前台，调不上来才提示「已经打开」。
- `Config.reload()` 只认白名单里的顶层键。新增配置键必须登记，否则保存了也读不回来。

## 后果

- 两个进程都会整份写配置。设置开着时主进程也在写（例如拖动后记位置），所以：
  需要立刻落盘的设置项只改盘上那一项，不整份写回；没动过的字段保存时不写回打开时的值。
- 设置进程跑的是它被拉起时的代码。更新代码后还开着的旧设置窗口看不到新设置项，在它里面点保存还会把新键丢掉。
- 恢复配置这类操作完成后，设置窗口要不保存直接关闭，否则表单里的旧值会盖回去。
- 设置里「测试连接」测的是表单，主进程查的是已保存的配置，没保存时两边说的不是一回事。
