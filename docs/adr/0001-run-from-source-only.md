# 0001：只从源码运行，不打包、不发版

日期：2026-10-11

## 背景

项目 fork 自一个发安装包、带在线更新的上游。本项目只在作者自己的机器上用，从 `run.bat` / `python -m pet` 启动。
三个平台的构建脚本、安装包定义、打包入口、发布工作流和产物自检每次改依赖或改名都要跟着维护，却从来不被执行。

## 决定

删掉构建与发布的全部基础设施：构建脚本、安装包定义、PyInstaller 入口、构建 / 发布工作流、产物瘦身与自检脚本及其测试、
打包指南、在线更新。

有意留下的，判据是「删它要不要改 `pet/` 下的运行代码」：

- 运行期给打包版准备的分支：`sys.frozen` 判断、`build_variant` 变体目录、`_MEI` 临时目录清理。
- 「无聊天变体」的延迟导入约束（`modern_settings_dialog.py` 顶层不 import `pet.chat`）及其架构守卫。
- `pet/uninstall_cleanup.py`：它移除注入到 Claude Code 的钩子，源码用户同样需要。
- `.github/workflows/pr-test.yml`：是测试门禁，不是打包。

没有选「连运行期的打包分支一起拆」：它们散在近十个模块里，拆掉要逐处补测试和实机验证，与减轻维护负担的目的相反。

## 后果

- 没有安装包，换机器要装 Python 环境。
- 代码里的 `sys.frozen` / `build_variant` 分支在源码运行时走不到，读代码时会多看几行；不要当成死代码顺手删。
- 要恢复打包：从 git 历史取回删除那次提交之前的文件。它们在删除前刚按新名字改过，那次改名没有经过实际构建验证。
- 上游还在维护这些构建脚本，同步上游时它们会以「我方删除、对方修改」冲突，每次保持删除（见 [0002](0002-cherry-pick-from-upstream.md)）。
