# 0018：生成出来的内容也在浏览器里读，从工作简报开始；Qt 的简报窗口等别的页搬完再删

日期：2026-11-19

## 背景

[0014](0014-panorama-becomes-the-console.md) 把**设置**搬到了配置全景（网页）。但肥鱼还有一类界面是**读生成出来的
内容**：工作简报、个人简报、工作笔记、Slack 关注，都在一扇 Qt 窗口 `WorkBriefingWindow` 里（三页，三处复用）。
它用 Qt 的文本控件排 Markdown，再逐个文本片段上色；每多一种标记就多一段遍历代码，样式和网页那边各一套。
用户 2026-11-19 说：先把工作简报搬到浏览器。

## 决定

- **内容页也走配置全景那个本机回环服务**，作为它的第二类页面：`/report/<名字>`（外壳公开、无数据）+
  `/api/report/<名字>`（要令牌，和图一样认 `?after=` 等更新）。内容**不进全景图、不落离线快照**：图是地图，这是读内容；
  快照落盘，公司内容不该多一份副本。肥鱼没开时没有报告可看（原来的 Qt 窗口也要肥鱼开着）。
- **页面不认功能**：服务里按名字登记 provider（`reports={"work_briefing": …}`），provider 在界面线程上把那项功能的状态翻成
  一份固定字段的字典（标题、概要、用量、全文 HTML、忙 / 错、按钮）。个人简报以后只是多登记一项。
- **Markdown 在 Python 里渲染**（`pet/panorama/markdown.py`，零依赖，只认简报会写出来的子集）；★ 和 bug 记号变成类名，
  样式在 `report.css`。逻辑留在 Python 可测；不引 markdown 库。
- **一次只搬一页。** 这一步只搬工作简报的阅读页：岛按钮、提醒的「查看」、菜单「查看最近一份」都开浏览器，Qt 里不再有
  第二个看它的地方。笔记页、Slack 关注页是交互列表，各自一期；个人简报紧随其后。**`WorkBriefingWindow` 先留着**只当别的页
  的壳（不带「简报」页），都搬完再删——现在删它等于同时重做三个功能。
- 页面跟「外观」里的主题偏好，不放自己的明暗切换：那个偏好只在一处改（0014）。
- 顺手按 0014 把菜单里「生成时间」子菜单拿掉（页面上已能改），换成一条「简报设置…」。

没有选「在全景图上加一块显示简报」：图是配置的地图，和读一篇文字是两件事，而且会把公司内容带进快照。
没有选「先删 Qt 窗口」：笔记 / Slack 页还靠它。
没有选「页面里用 JS 渲染 Markdown」：渲染规则要和原来 `_decorate` 的上色一致，在 Python 里有测试守着更稳。

## 后果

- 本机服务多两个网址、一类页面；`PanoramaService` 多了报告登记表、`open_report`、`publish_report`。
- 简报内容第一次经 HTTP 给浏览器（仍只在 `127.0.0.1`、要令牌、只记请求行）；隐私边界不变。
- 工作简报的阅读界面从此有两套样式令牌来源：Qt 壳（`_EXTRA_TOKENS`）和 `report.css` 顶部那组，改一处要两处一起改，
  直到 Qt 壳删掉。
- 剩下的顺序记在[路线图](../roadmap.md)「内容页搬到浏览器」。
