# 0022 配置全景的本机服务跟着肥鱼起停，端口和令牌跨重启保留

- 状态：已采纳（2026-11-27）
- 相关：[0014](0014-panorama-becomes-the-console.md)、[0015](0015-private-repos-are-home.md)

## 背景

配置全景和各张报告页都由 `127.0.0.1` 上的本机服务供数。原来服务 15 分钟没请求就自停，每次启动换端口、换令牌。
标签页切到后台时不挂请求，所以放一会儿再切回来，或者肥鱼重启过（并行会话常重启桌宠），页面就亮出「连接断了」，
只能从肥鱼里再打开一次。用户提议「本机发出的请求不检查、直连」。这条不能做：服务只绑回环，所有请求本来就来自本机，
包括浏览器里任何网页发来的；豁免本机等于拆掉全部守门（读文件、改会交给 AI 执行的提示词）。

## 决定

- **守门一道不减**：Host、来源、`Sec-Fetch-Site`、令牌、JSON 照旧。
- **服务不再空闲自停**，跟着肥鱼起停。
- **端口和令牌记在数据目录的 `panorama-session.json`**，下次启动用回同一个端口和令牌。端口被占就换一个空的，令牌照旧。
  用过配置全景的话（文件在），肥鱼启动 5 秒后就把服务起起来；从没用过的话，启动时什么都不做。
- **页面断了自己重连**：连不上或服务回 5xx 时亮出「正在重连」，每 3 秒不带编号重新要一份（重启后编号从头数）；
  回 4xx（令牌对不上）才是真断了。发布台是空的时候（刚重启），服务安静地采一轮给它，不开浏览器。

## 后果

- 令牌在磁盘上活得比一次运行长。网页读不到磁盘，所以守门强度不变；本机别的程序本来就能读肥鱼的配置，也不算新的暴露面。
  文件丢了只是开着的标签页要从肥鱼里再打开一次（存储表：`disposable`）。
- 「不点就不跑」放宽了：用过配置全景之后，每次启动多一次约 60 毫秒的界面线程工作（import + 起服务），外加一个常驻的服务线程，
  它每 2 秒醒一次（实测 60 秒 CPU 低于 Windows 计时粒度 15.6 毫秒）。
- 想推翻的话：把会话文件删掉，`PanoramaServer` 不给 `session` 就回到「每次随机端口、新令牌」。空闲自停已经删掉了，要的话得重新加回来。
