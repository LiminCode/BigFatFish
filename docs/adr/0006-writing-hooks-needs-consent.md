# 0006：往 Claude Code 的设置里写 hooks，每次都要用户同意

日期：2026-11-15

## 背景

会话小鱼的状态靠注入到 `~/.claude/settings.json` 的 hooks。两种情况会出现「联动开着、hooks 却不在」：
配置被重置成默认值（联动默认开），或者 hooks 被别的东西卸掉。这时鱼还在，但状态不动，也没有等批准的提醒。

## 决定

联动的开关默认是开的，但开着只表示启动监视器。写 `settings.json` 只有一条路：用户在同意弹窗里点了「是」。

- 应用配置、启动、迁移都不写 hooks。数据目录改名后只**更新**已经注入过的 hooks 里的路径，从不新装。
- 发现 hooks 缺失时只提示：冒一条气泡，右键菜单里多一条修复项。修复项弹的是同一个同意弹窗，点「否」什么都不写。
- 判断不了就不提示（那一侧没有 `~/.claude`、WSL 没响应、设置文件不是合法 JSON）。
- 只在通道启动时检查一次，不周期检查。

没有选「发现缺了就自动补上」：那是在用户不知情时改另一个程序的配置。

## 后果

- 全新安装之后「联动开着但没有 hooks」是常态，直到用户同意一次。
- 运行中被卸掉的 hooks，要到下次启动肥鱼或重新开关联动才会提示。
- hook 事件表加了新事件，老用户会看到缺失提示，重新同意一次才装上。

## 补记（2026-11-19）

配置全景的待处理里有了「修复」按钮：同意框是页面上的 `confirm()`，文案和上面那个弹窗一样，点「取消」什么都不发；
点「确定」才 `POST /api/actions/repair_hooks`，主进程只做「装」那一半（`install_hooks_consented`）。这仍是「用户明确同意之后才写」
那一条路，只是同意框从桌面搬到了用户正看着的页面。打开通道的开关（菜单或页面）照旧只起监视器，不写 hooks。
