# 0014：配置全景长成主控制台，设置逐步从 Qt 窗口搬到网页，经本机回环服务读写

日期：2026-11-15

## 背景

配置全景第一期是一张只读的本地页面（`file://`），看得见配置却改不了：页面不能写文件，也不能回调肥鱼。
要改一项设置，得另开 Qt 设置窗口再找到那一页。那扇窗有 11 个域、约 250 行设置项，全是手写控件，
没有一张统一的设置表，新增一项要改四五处。
用户给项目定的目标是：一切流、设置、存储、内容都要看得见，而且能在看见的地方配置。

## 决定

- 配置全景是肥鱼的主控制台。设置**全部**搬到网页上，按域分很多小步走；搬完后下线 Qt 设置窗口。
- 搬一组设置的那个 PR 里，同时把这组从 Qt 窗口删掉，原处只留一个跳转。任何时刻一项设置只有一个编辑入口。
- 页面改由肥鱼主进程里的一个**本机回环服务**提供，并通过它读写。这推翻了第一期「不开端口」的取舍。
- 这个服务只绑 `127.0.0.1`、随机端口，用户点了才启动，空闲自停。每个请求查 Host 白名单；
  写请求再查来源和每次启动随机生成的令牌。提示词会交给带工具的 AI 执行，所以这三道校验一条都不能省。
- 写设置只有一条路：进主进程的 GUI 线程，按设置表校验后由活的 `Config` 落盘。带版本号，旧页面写不进去。
- 页面保持很薄：不认识任何具体功能，也没有写死的文案。设置、存储、动作各有一张声明式登记表，
  页面按表画通用控件；校验和测试留在 Python。
- 密钥只进不出：页面只知道「有没有」和末 4 位。

没有选「只搬 AI 类设置」：两套界面长期并存，等于两处维护。
没有选「页面内嵌进肥鱼（浏览器内核控件）」：多一个几百兆的依赖，违背设置进程当初独立出去的理由。
没有选「自定义网址协议回调」：只能单向发命令，页面拿不到结果。
没有选「页面直接写配置文件」：浏览器不允许，绕过去也就绕过了校验。

## 后果

- 多了一个监听端口和一套 HTML / JS。页面一侧的测试手段比 Qt 弱，所以逻辑必须留在 Python。
- 在 Qt 设置窗口下线之前，[0011](0011-settings-is-a-separate-process.md) 继续有效；两边并存期间靠
  「搬一组删一组」避免互相覆盖。
- 新增一项设置从「写控件 + 写保存」变成「在设置表里声明一次」。漏登记由守卫测试拦。
- 浏览器拿不到本机绝对路径：选文件、选文件夹这类操作要回到肥鱼进程里弹系统对话框。
- 肥鱼没开时页面不能改东西，只能看离线快照。
