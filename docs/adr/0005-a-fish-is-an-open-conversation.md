# 0005：一只会话小鱼就是一个开着的对话

日期：2026-11-02（2026-11-14 补充）

## 背景

会话小鱼最初只靠 hook 事件生灭：会话干活时才出现。结果是肥鱼一重启，空闲的会话全没了鱼；
联动被关掉时，正开着的对话被当成「最近开过、已经关了」而显示成冻结。

## 决定

鱼表示「这个对话开着」，不是「这个对话正在干活」。

- Claude Code 自己写的运行中会话清单（`~/.claude/sessions`）是第二个数据来源：启动时和之后每分钟从它认领开着的会话。
  没有通道在喂的会话，由界面一侧按本机清单认领。
- 最近几天开过、进程已经不在的对话，是一只灰色的冻结鱼，可以从它重开。
- 用户「关闭这只」的决定落盘、跨重启；那个会话再次活跃（开始干活或等批准）时作废。
- 「等你回复」是界面一侧派生的状态：回合结束而用户还没点过去看。它只在内存里，不进事件收敛器。

没有选「只把活着的会话从冻结名册里排除」：那样活着的对话会没有鱼。

## 后果

- 依赖一个没有文档的内部格式；清单读不到时鱼退回只靠 hook 事件。
- 认领来的会话没有结束事件：在清单里见过、又连着两轮查不到，才算关闭。
- 肥鱼自己起的无界面运行必须带标记，否则会被认领成一只停不下来的鱼（见 [0003](0003-two-accounts-two-channels.md)）。
- 用户自己切过去看了但没回复的对话，会一直显示「等你回复」。
