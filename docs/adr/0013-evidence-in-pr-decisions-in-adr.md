# 0013：交付证据写在 PR 描述里，仓库里只留主题文档、变更记录和 ADR

日期：2026-11-15

## 背景

2026-09-22 起每个 PR 都要在 `docs/` 新增一份报告（修改文件说明、性能分析、实机运行记录），并在索引登记，有测试强制。
不到两个月攒了 87 份报告、约 1.2 MB，外加 129 张截图。索引本身长到 84 KB。真正长期有用的内容
（取舍、不变量、坑、排障手法）埋在逐文件行数和当时的命令输出里，同一个子系统的现状要拼好几份报告才看得全。

## 决定

- 三份证据仍然是每个 PR 的硬要求，但写在 **PR 描述**里（模板 `.github/PULL_REQUEST_TEMPLATE.md`）。
  它们描述的是那一次改动，和那个 PR 放在一起，git 历史里不再多一份文件。
- 仓库里的文档按主题组织，一个子系统一份，写现状。机制、不变量、排障结论变了，在同一个 PR 里改它。
- 用户看得见的变化在 `CHANGELOG.md` 加一行。
- 只有大改动才新增文档，形式是 ADR：新的功能域、架构边界变了、一个将来有人会想推翻的取舍、下线一个功能。
- 截图不入库。
- 87 份旧报告提炼进主题文档和 ADR 后全部删除，原文在 git 历史里。

考虑过又没选的：保留每个 PR 一份报告但挪进子目录（文档照样每个 PR 长一份）；完全不留仓库内文档，只靠 PR 描述
（子系统的现状没有地方写）。

## 后果

- `docs/` 的文件数不再随 PR 数增长。
- 证据在 GitHub 上，离线或换托管平台时看不到；真正要长期留的结论必须进主题文档或 ADR，不能只写在 PR 里。
- 「什么算大改动」靠判断，测试校验不了，只能校验 ADR 的形式和登记。
- 主题文档会过时：改代码的 PR 没有顺手改文档时，没有机器能发现。审查时要看 PR 模板里 Docs 那一栏。
