## 一、核心特性

用户反馈右下角通知栏里的图标太小。原因是可测量的：托盘图标取自**角色当前帧**，裁掉
透明留白后**等比**缩进托盘的方格里，角色不是方的，图标就填不满。

| 角色（待机首帧） | 64×64 方格里的实际尺寸 | 可见面积占方格 |
|---|---|---|
| `shenshen`（用户当前使用） | 50×64 | 52% |
| `claude` | 32×64 | 29% |

新增设置「托盘图标」：指定一张自己的图片就用它；没指定、文件不在或不是图片，就回到
默认的角色头像。

**红线 / 不变量**

- 没填时行为与改动前相同：`load_custom_pixmap("")` 直接返回 `None`，走原来的取图链
  （既有的 `tests/test_overlay_tray_icon.py` 4 条全部通过）。
- 指定的文件用不了时**不报错、不弹窗**，静默用默认图标；设置页那一行的说明文字会
  变成「这个文件用不了…」。
- 自定义图片不拉伸、不裁内容，只裁透明留白。

**只做了单合成窗（overlay）这条路径。** `AGENTS.md` 规定 `PetWindow` 那条旧路径只修
崩溃不加功能，所以 `app.py` 里旧托盘的建造代码没有动。

## 三、实现要点

**为什么自定义图片要挡在「首帧刷新」前面。** 托盘建造时角色首帧往往还没解码，所以壳里
有一个轮询：先放爪印占位图标，拿到角色帧后换上。如果只在建造时用自定义图片，这个
轮询几百毫秒后就会把它换回角色头像。所以 `_refresh_tray_icon_once()` 也先问自定义
图片——有它就算「已换好」，轮询随即停表。

**即时生效。** 设置窗口是独立进程，保存后主进程的配置 watcher 重载配置并调
`OverlayShell.refresh_settings()`。那里新增一步：重新决定托盘该用哪张图。从自定义改回
默认时，若角色帧恰好还没就绪，则重新进入轮询等首帧。

**一个踩到的坑：配置键白名单。** `Config.reload()` 不是把磁盘上的键全读进来，而是按一份
写死的键列表逐个取。新键不加进去的表现是：`set` + `save` 都成功、磁盘上也有，但下一个
`Config()` 读出来是默认值。测试 `test_settings_offer_a_tray_icon_picker_that_persists`
第一次运行就是红在这里。仓库里其实有专门守这件事的快照测试
（`tests/test_config_schema.py`），但它不在我选的聚焦测试集里，直到全量才报出来。

**存的是绝对路径，不复制文件。** 与对话背景、自言自语配图目录等已有的自定义图片设置
同一约定。代价是原文件被移动或删除后图标回到默认（这是有意的退路，不是错误）。

**设置准入记录**

```text
setting_id            tray_icon
domain_id / group_id  常规 / 窗口与系统
default               空（用角色头像）
capability            仅单合成窗拓扑；三个平台共用同一个键与语义
disclosure_level      primary
dependency            无
commit_policy         on_finish
migration             新键，无旧键
recovery              清空即回到默认；文件不可用时自动回到默认
```

## 四、性能分析

**方法**：一次性脚本（会话内，未入库）调用 `pet.tray_icon` 的函数实测。环境：Windows 11
10.0.26300，Python 3.13.15，PySide6 6.12.0。

| 指标 | 实测 | 归属 |
|---|---|---|
| 没设置自定义图标（n=2000） | 中位 0.10 µs | 新增，每次取托盘图标时多这一步 |
| 设了路径但文件不存在（n=2000） | 中位 8.3 µs | 新增 |
| 读一张自定义图标（`assets/icon.ico`，n=200） | 中位 0.16 ms，最大 0.29 ms | 新增 |
| 自定义图片的可见面积占比 | 应用图标 `icon.ico` 55%（51×64）；一张不透明照片 89%（57×64） | 对照上表的 52% / 29% |
| 新测试文件 | 9 条，与托盘 / 岛头像 / 架构测试合计 31 条 2.6 s | — |

**结论**

1. **稳态开销**：没设置时每次取托盘图标多 0.10 µs。取图发生在托盘建造、首帧轮询
   （每 500 ms 一次，拿到帧即停）和每次配置变更时，不在每帧的热路径上。
2. **新增路径**：设了自定义图片时，上述每个时机读一次文件（0.16 ms 量级，随图片大小
   而变；没有做大图的测量）。没有缓存：配置变更不频繁，而缓存要处理「文件被替换」。
3. **新的系统调用 / 网络 / 磁盘 / 线程**：磁盘上多一次 `stat` 和一次图片读取（仅在设了
   路径时）；无网络、无新线程。
4. **内存**：一张 64×64 的位图，由托盘图标持有；不常驻原图。

## 七、已知限制与后续

- 只支持单合成窗拓扑；旧的 `PetWindow` 托盘不读这个设置。
- 非方形的图片仍然填不满方格（不拉伸、不裁内容是有意的）。可以加一个「居中裁成方形」
  的选项，本次没做。
- 动图只取第一帧。
- 灵动岛上的头像不受这个设置影响，仍是角色当前帧。
- 存的是绝对路径：换机器或移动图片后需要重新选择。

## 八、风险与回滚

- **影响面**：托盘图标的取图；没设置时与之前相同。
- **新增配置键**：`tray_icon`（字符串）。旧版本读不到它（不在旧版本的键白名单里），
  也不会保留它。
- **回滚**：`git revert` 即可，无残留状态。
